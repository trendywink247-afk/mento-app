## The transition system you are expressing (the six principles)
1. **One continuous sky.** The background never cuts. A soft aurora (2–3 large radial-gradient blobs on the oat ground, as in `A01_Landing`) persists through a whole flow and only *shifts* — position and hue drift a little per screen. Content moves over it.
2. **The companion travels.** The member's companion is a shared element: it does not disappear and reappear, it *moves* to its next perch (translate + scale), arriving just before the content it sits on.
3. **Things come from where you touched.** A tapped key or row is the origin of what opens: the next surface grows out of it (scale/translate from the key's position), and returns into it on back.
4. **Leave fast, arrive slow — never two headlines at once.** Outgoing content is gone (opacity 0) before incoming text is readable: exit 200ms, a breath, enter 350–500ms with an 80ms stagger by reading order. This is the rule the old build broke.
5. **Direction means something.** Forward in a flow = content rises and the old drifts up and away; back = the exact reverse. Tabs move laterally in tab order, and the sky drifts the opposite way at a fraction of the distance (parallax). Sheets rise from the bottom while the screen behind settles back (scale 0.96, dimmed) — depth, not a fade.
6. **Calm, always.** Transform and opacity ONLY (never width/height/top/left/margin). Durations from the token scale 200 / 350 / 500 / 700 ms; easing `cubic-bezier(0.22, 1, 0.36, 1)` for arrivals, `cubic-bezier(0.4, 0, 1, 1)` for exits; no bounce, no overshoot. Under `prefers-reduced-motion: reduce` every transition becomes a ≤150ms opacity swap with no movement — write that as an explicit `@media (prefers-reduced-motion: reduce)` override block. Error, limit and crisis states never animate at all.

## How to build a playable prototype in this format
- One artboard = one phone, root `width: 390px; height: 844px; overflow: hidden; position: relative`. BOTH (or all) screens of the hand-over live inside it as absolutely-positioned layers. State in the Component class says which screen is showing; tapping the REAL control (the actual CTA, row, tab, or back key) flips the state. CSS `transition` rules (in `<helmet><style>`, on STATIC classes such as `.mv { transition: transform 500ms cubic-bezier(0.22,1,0.36,1), opacity 350ms cubic-bezier(0.22,1,0.36,1); will-change: transform, opacity; }`) do the animating. The STATE is delivered through inline-style holes, which is the only hole position proven to work on this board — **never put a `{{hole}}` inside a `class` attribute**. Example: `<div class="mv" style="position: absolute; inset: 0; opacity: {{ forkOp }}; transform: {{ forkTf }}; transition-delay: {{ forkDelay }}; pointer-events: {{ forkPe }};">` with `renderVals()` returning `forkOp: on ? 1 : 0, forkTf: on ? 'translateY(0px)' : 'translateY(24px)', forkDelay: on ? '280ms' : '0ms', forkPe: on ? 'auto' : 'none'`. Different delays for entering vs leaving come from the same hole (enter delayed, exit 0ms). For exits that need the faster exit curve, use a second static class (`.mv-slow`, `.mv-fast`) on different elements rather than switching classes. Always drive `pointer-events` by state so hidden layers cannot be tapped.
- Reduced motion block: `@media (prefers-reduced-motion: reduce) { .mv { transition: opacity 150ms linear !important; transition-delay: 0ms !important; transform: none !important; } }` — a stylesheet `!important` beats the inline value. Shared elements whose resting POSITION is a transform (the travelling companion, the tab indicator) must use a different class (`.perch`) whose reduced rule is `transition: none !important` only, so they jump to the new perch without moving through space.
- Every prototype must be replayable forever: forward by tapping the real control, back by the back key (or tapping the scrim / the other tab). No dead ends. Add one small quiet caption inside the phone's bottom safe area ONLY if the thing to tap is not obvious.
- The persistent layers (sky, companion) sit OUTSIDE the per-screen layers so they visibly never cut. Move the companion by switching a state class that changes its `transform` (translate/scale) — never its `left/top`.
- Rebuild screens at enough fidelity that the founder recognises them (real copy, pillow keys, the right art), but you may simplify long lists. Real `<button>`/`<a>` elements; `aria-label` on icon-only keys; touch targets ≥ 44px.
- `is_interactive` is set in the board index by someone else — just make it work.
- Output to `...\scratchpad\mento-design\project\<FileName>.dc.html`. Give each artboard its own `<title>`.

When finished reply with: the files written; for each, what you tap, what moves and in what order (with the ms you used); anything that could not be done with transform/opacity alone; and any spec deviation.
