Stillness Error, limit reached, crisis card, under-age block, disabled key 0 px no motion · at most a 150 ms opacity change No haptic, no motion. Stillness is the signal (T&S #11); no verb exists for it. Stop and read. Nothing is pushing you.

Android reality. Many mid-range Android phones render every impact style as the same short buzz, so a haptic is never the only signal: travel and tempo carry the meaning. Honour the system touch-feedback setting. Under reduced motion, travel becomes a 150 ms opacity dip and haptics stay single, never added to compensate.

Key anatomy

Rest edge 4 px
Pressed face +4 px
Released back to 0

Face. The only part that moves.

Edge. Solid, no blur. Depth 4 px; chips 3, hold 5.

Travel. Set by intent, never more than depth.

Reduced motion. No travel, a 15% opacity dip.

Never

  • No audio, shake or flash.
  • No bounce or overshoot.
  • No haptic on scroll or typing.
  • No haptic loops or patterns.
  • No Warning or Error haptic.
  • No second haptic on one press.
  • Nothing at a struggling person. Errors, limits, the crisis card and the age block stay still. T&S #11.

Today, read from the source

Committed. PressKey travel 4 | 3 | 2, edge equals travel; in withTiming(1, duration.fast / 2, easing.exit), out withSpring(0, spring.calm); reduced motion swaps travel for a 15% opacity dip; disabled is silent and still. Every key fires the same haptic.advance() (Light). lib/haptics.ts has tick(), advance(), success(), nudge() and no error verb.

Uncommitted, in the working tree. PressKeyIntent commit | navigate | select | toggle; haptic.commit() Medium; haptic.toggle() Soft; commit press-in 120 ms; a note save fires success() once it resolves.

Gaps. goNext() and onRolePicked() call haptic.advance() on top of the key's own: two buzzes per tap. Press-in eases in, so the first frames lag. No press-and-hold exists. A confirmed send fires nothing. No error path calls a haptic; keep it so.
